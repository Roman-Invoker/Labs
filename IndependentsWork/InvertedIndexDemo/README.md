# Самостійна робота №10. Інвертований індекс і вимірювання продуктивності

**Проєкт:** `InvertedIndexDemo` (консольний застосунок C#, .NET 8)

Звіт з описом реалізації, таблицею вимірювань і висновками: **[REPORT.md](REPORT.md)**.

---

## Що реалізовано

| Файл | Призначення |
|------|-------------|
| `Document.cs` | модель документа (`Id`, `Title`, `Content`) |
| `TextProcessor.cs` | `Tokenize` (нижній регістр, `\w+`, без пунктуації) та `RemoveStopWords` |
| `InvertedIndex.cs` | індекс `Dictionary<string, HashSet<int>>` + `Dictionary<int, Document>`; методи `AddDocument`, `SearchSingleWord`, `SearchMultipleWords` (AND, `IntersectWith`), `SearchAnyWord` (OR, `UnionWith`) |
| `DocumentGenerator.cs` | п'ять документів із завдання та генерація 100 / 1000 / 10000 документів |
| `PerformanceTest.cs` | лінійний пошук, `CompareSearchMethods`, усереднені вимірювання, таблиця у форматі Markdown |
| `Program.cs` | інтерактивний пошук і режим вимірювання (`benchmark`) |

Ключові рішення:

- **Єдина нормалізація.** Документи, запити та лінійний пошук використовують `TextProcessor.Tokenize`. Тому запит `C#` перетворюється на `c`, так само як і слово в документі, а порівняння швидкості коректне.
- **Стоп-слова вимкнено за замовчуванням** (`new InvertedIndex(removeStopWords: true)` вмикає їх). Інакше індекс не знайшов би слово `is`, а лінійний пошук знайшов, і кількості результатів розійшлися б.
- Результати пошуку впорядковано за `Id`, бо порядок обходу `HashSet` не гарантований.
- Під час AND-пошуку перетин починається з найменшої множини документів.
