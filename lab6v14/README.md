# Лабораторна робота №6 — Наслідування (`base`, `virtual`, `override`, `new`)

**Дисципліна:** Об'єктно-орієнтоване програмування

## Опис ієрархії

| Клас | Роль | Поля / властивості | Методи |
|------|------|--------------------|--------|
| `Electronic` | базовий | `Brand`, `PowerConsumption` (приватні поля + публічні властивості з перевіркою) | конструктор, `virtual void TurnOn()`, `string GetElectronicType()` |
| `Television` | похідний | `ScreenResolution` | конструктор з `base(...)`, `override TurnOn()`, `ChangeChannel(int)`, `new string GetElectronicType()` |
| `Radio` | похідний | `FrequencyRange` | конструктор з `base(...)`, `override TurnOn()`, `TuneStation(double)` |

`Television` та `Radio` успадковують `Electronic` напряму. Обидва викликають `base.TurnOn()` у своєму `override`, тому спочатку виконується частина базового класу, а потім власна.

### Що демонструє вивід

- **Розділ 2.** Масив типу `Electronic[]` містить три різні об'єкти, і для кожного викликається «своя» версія `TurnOn()`. Це поліморфізм через `virtual`/`override`.
- **Розділ 4.** Об'єкт один і той самий, але:
  - `TurnOn()` (`override`) через посилання `Electronic` все одно виконує версію `Television`, бо вибір робиться за **типом об'єкта** під час виконання;
  - `GetElectronicType()` (`new`) через посилання `Electronic` повертає версію базового класу, бо вибір робиться за **типом посилання** під час компіляції.

## Відповіді на контрольні питання

**1. Принцип наслідування. Приклад з реального світу.**
Наслідування дозволяє створити новий (похідний) клас на основі існуючого (базового). Похідний клас отримує його поля, властивості й методи та може додавати власні або змінювати успадковані. Так формується ієрархія «є різновидом». Приклад: «Транспортний засіб» має марку й рік випуску, «Автомобіль» і «Мотоцикл» мають усе це, а також свої особливості (кількість дверей, наявність коляски). У цій роботі так само `Television` та `Radio` є різновидами `Electronic`.

**2. Для чого використовується `base`?**
Ключове слово `base` дає доступ до членів базового класу з похідного. Основні застосування:
- виклик конструктора базового класу: `Television(...) : base(brand, powerConsumption)`;
- виклик версії методу з базового класу всередині `override`: `base.TurnOn();`, щоб розширити поведінку, а не переписувати її повністю.

**3. Різниця між `virtual` і `override`. Як вони забезпечують поліморфізм?**
`virtual` у базовому класі позначає метод, який похідні класи **можуть** перевизначити. `override` у похідному класі надає нову реалізацію цього методу. Під час виклику через посилання базового типу середовище виконання (за таблицею віртуальних методів) вибирає реалізацію за **фактичним типом об'єкта**. Завдяки цьому один і той самий код `d.TurnOn()` працює по-різному для `Electronic`, `Television` та `Radio`.

**4. Коли використовувати `new` і які наслідки?**
`new` явно приховує успадкований член, коли в похідному класі потрібен метод з тим самим іменем, але без поліморфної поведінки (наприклад, не можна змінити базовий клас або метод не має бути віртуальним). Наслідок: який метод буде викликано, залежить від **типу посилання**, а не об'єкта. Через посилання `Television` викликається нова версія, через посилання `Electronic` — стара. Це може призводити до неочікуваної поведінки, тому в більшості випадків краще використовувати `virtual`/`override`, а `new` застосовувати свідомо. Без `new` компілятор видасть попередження CS0108.
