# Лабораторна робота №2. Варіант 14 (`Restaurant`)
**Тема:** Клас із кількома конструкторами. Життєвий цикл об’єкта  
**Дисципліна:** Об’єктно-орієнтоване програмування  
**Навчальний заклад:** Рівненський фаховий коледж інформаційних технологій  
**Інструменти:** .NET SDK 8.0+, C#, IDE (Visual Studio / JetBrains Rider / VS Code)

---

##  Мета роботи
Опанувати створення класів C# з перевантаженими конструкторами, реалізувати ланцюговий виклик конструкторів за допомогою ключового слова `: this()`, встановити валідацію для властивостей та дослідити життєвий цикл об'єкта (створення, використання, деструкція через Збирач сміття `Garbage Collector`).

---

##  Завдання за варіантом №14

Створити клас **`Restaurant`**, який містить:
* **Приватні поля:**
  * `_name` (`string`) — назва ресторану;
  * `_cuisine` (`string`) — тип кухні;
  * `_rating` (`double`) — рейтинг ресторану.
* **Публічні властивості:**
  * `Name`, `Cuisine`;
  * `Rating` — з валідацією значення в межах **від 1.0 до 5.0**.
* **Конструктори:**
  * **Параметризований:** `Restaurant(string name, string cuisine, double rating)` — основний конструктор ініціалізації.
  * **За замовчуванням:** `Restaurant()` — викликає параметризований конструктор через `: this("Unnamed", "Mixed", 3.0)`.
* **Метод:**
  * `ServeDish(string dishName)` — виводить у консоль повідомлення про подачу страви.
* **Деструктор (фіналізатор):**
  * `~Restaurant()` — виводить у консоль повідомлення про видалення об’єкта з пам'яті Збирачем сміття.

Що таке перевантаження конструкторів і яку перевагу воно дає?

        Відповідь: Перевантаження конструкторів — це можливість визначати в одному класі декілька конструкторів з однаковим іменем, але різними параметрами. Це надає гнучкість при створенні об'єктів з різним набором початкових даних.

    Як за допомогою : this() можна уникнути дублювання коду ініціалізації?

        Відповідь: Конструктор з легшим набором параметрів передає управління основному конструктору через синтаксис : this(...), заповнюючи недостатні параметри значеннями за замовчуванням. Це дозволяє зосередити всі перевірки й присвоєння в одному місці (принцип DRY).

    Хто і в який момент викликає деструктор (фіналізатор) у C#?

        Відповідь: Деструктор викликається Збирачем сміття (Garbage Collector) перед видаленням незадіяного об'єкта з пам’яті (купи). Точний час виклику автоматичний і не контролюється розробником напряму.

    Чому в реальних програмах не рекомендується викликати GC.Collect() вручну?

        Відповідь: Виклик GC.Collect() призупиняє виконання потоків додатка (Stop-the-World), порушує внутрішню оптимізацію розподілу об'єктів за поколіннями та суттєво знижує продуктивність програми.
